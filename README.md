# 宏穩茶水間 · Holdwin Pantry

公司飲料的手機網站：同事開冰箱、看品項、許願；管理者在倉庫盤點與記錄到貨。採用暖白香檳金與公司 H 圖標，包含 32 款供應中飲料與 8 款歷史品項。

## 目前功能

- 牛奶／豆漿放在第一層，其餘依茶飲、咖啡、果汁、汽水與其他分類；八種包裝各有不同示意外觀。
- 關門顯示「點擊打開冰箱門」，開門動畫完成後才可在冰箱內向下滑動；支援手機及減少動態設定。
- 後台庫存分為飲料、零食、冰品、泡麵與碳粉。零食先建好多力多滋雙倍起司口味、多力多滋香菜口味、樂事海苔口味、華元洋芋片（蚵仔煎口味），分類為太空包、單位為包、初始數量尚未確認。泡麵初始包含六款指定品項（含辛拉麵，單位為杯），分別以杯／碗登記；碳粉固定黑、黃、紅、藍四色，單位為盒。兩類只登記單位數量、不換算整箱，初始均待盤點；每列有快速入庫與盤點，並保留登記人與時間。
- 冰品可在到貨頁選「其他／新品」建立，單位可選支、杯、盒、包、個、桶。首次庫存直接採用入庫量，支援批次入庫、快速盤點、手動補貨與分類總量；歸零進歷史品項，重新入庫恢復供應。冰品不預建商品、無自動效期提醒，前台冰箱維持飲料。
- 到貨入庫分成「飲料／零食／冰品／泡麵／碳粉」五個子頁，各有入庫表單與最近紀錄；切換前保護未儲存輸入。泡麵入庫必填保存期限，按批次保留不同日期；庫存頁提醒 30 天內到期、今天到期及已到期，並可標記某批已用完。功能啟用與逐步更新見 [泡麵與碳粉設定](docs/SUPPLIES-SETUP.md)。
- 入庫選單依紀錄庫存由少到多排列，待盤點放後，不標示需要補貨。飲料、零食與泡麵可選「其他／新品」展開名稱與單位，將新品與本次到貨一起保存；同名品項不重建，圖片和營養資訊可之後補齊。新品初始總量待盤點，飲料每箱量待設定；碳粉維持固定四色。
- 零食入庫可先依七種分類（含蛋白質零食）及品名／品牌／口味搜尋；找不到時按「新增零食」，名稱、分類、單位及本次到貨一起儲存。同名品項不重建。零食免填保存期限、不顯示效期提醒，舊日期紀錄保留；各口味分開紀錄，可手動勾選「需要補貨」。
- 零食補貨勾選不受數量限制，尚未確認數量、0 或高庫存都能標記；總覽另列共用補貨清單。入庫與更新數量不會自行取消勾選，標記不改動數量。零食表顯示「紀錄數量／最近數量更新」，需要時再更新單一品項即可。
- 既有泡麵盤點後可「補登效期」，依現場拆成多批，各批合計須等於目前庫存。只更新保存期限提醒，不增減庫存、不另建入庫或盤點；保留原紀錄、支援過期日期，並防止覆蓋另一裝置的新登記。
- 所有分類都由人工勾選「需要補貨」；已勾選品項排最前、數字標紅，其餘依數量由少到多，尚無數量紀錄放最後。飲料／零食的「庫存量少」為 1–10、泡麵為 1–3；0 獨立在無庫存，碳粉保留 0 的瀏覽範圍。數量門檻只供篩選，不自動標記補貨。勾選不改數量，入庫及盤點後保留，直到手動取消。
- 首次到貨即以已登記入庫量建立紀錄數量，後續實際盤點再校正；既有未盤點但有入庫的商品也會顯示數字，不補造盤點事件。
- 各到貨子頁可開啟「批次多品項入庫」，最多 30 列，可混合五個分類、既有與新品，共用登記人、一次送出。泡麵每列必填保存期限，同品項不同效期可分列。整批先驗證，按來源表合併寫入；儲存回條與重試識別碼避免重複入庫。
- 零食品名與選填口味分開保存，既有商品可編輯且沿用 ID；相同品名不同口味可建立，相同品名與口味不重建。庫存 CSV 與口味統計分欄顯示；平均每週消耗只使用有效實際盤點區間，資料不足顯示累積盤點中。快速盤點提供五類分頁。
- 後台首頁顯示跨分類最近入庫，以及每類最近一次實際盤點的數字與單位；管理入口留在功能列。補貨、量少與無庫存清單預設收合。摘要沿用單次精簡 Google 讀取，不先載入完整倉庫歷史。
- 開門後上方顯示熱門飲料前三名與平均每週包／瓶／罐數，依實際盤點及期間入庫估算；紀錄不足顯示「累積盤點中」。手機使用較小顯示素材，飲料照片開門後才載入；回訪先顯示已讀取的公開清單，再背景同步。計算與載入量測見 [效能說明](docs/PERFORMANCE.md)。
- 桌機使用依空間原照重繪的暖白、香檳金手繪辦公室插畫：四門冰箱、霧面電視與城市窗景，長桌延伸至畫面右側，兩側各有一排木椅，冰箱上不放便條貼。依桌機視窗比例選擇橫幅或窄高構圖，開門位置同步對齊；手機維持原本的單門冰箱。原始插畫尺寸與來源見 [插畫說明](docs/ARTWORK.md)。
- 桌機冰箱左側以小型雲朵框顯示「點擊打開冰箱」，雲朵不帶尖角尾巴，旁邊搭配短小的手繪迴圈箭頭；兩者共用咖啡金描邊、暖白填色與柔和陰影，呼應背景插畫。縮放或裁切後箭頭仍指向門片。點標示或冰箱門均可開啟，四扇門後有飲料層架，約 0.65 秒連續拉近飲料區，不停在白色空方塊，完成後顯示搜尋與分類。使用原色 Logo，小型鐵罐照片以一般尺寸的 80% 呈現，底部對齊層架。
- 手機後台的六個功能以每排三個、共兩排呈現，避免圖示與文字重疊；頁面、區塊、品項與彈窗標題統一使用網站自帶的手寫字型。網站用字優先載入精簡檔，新輸入的文字由同款完整字型補足，詳見 [字型來源](docs/TYPOGRAPHY.md)。
- 同事的冰箱只顯示品項與包裝，**不顯示餘量**。
- 商品照片與示意圖可混用；已套用全部 40 款確認的原圖，包含 8 款歷史品項。網站依商品輪廓透明呈現，移除白底與外部陰影，保留原始包裝、白色標籤與文字；目前既有品項皆已補齊。來源對應見 [圖片清單](docs/PRODUCT-PHOTOS.json)。後續自行上傳與自動去背功能延後至首版上線後處理。
- 管理後台與倉庫可快速新增飲料，只填品名、分類、包裝與登記人；沒有圖片先用示意包裝上架，數量留待實際盤點或入庫。Google 模式在網站內填表，送出並同步後才上架；同名品項不重複新增。
- 倉庫清單顯示實際紀錄庫存，**10 包／瓶／罐以內（含 10）標紅**；未盤點顯示待盤點；既有與新增品項的每箱數量統一預設為 24。
- 管理入口免登入；盤點及到貨入庫必填登記人，自動保存時間與數量。盤點至少填一個品項，留白保留原紀錄、填 0 表示實際為零；入庫可只填整箱或零散數量，兩項都填會加總。定期盤點校正日常取用，無須每天記錄。
- 統一使用「採買許願池」入口，在頁內篩選全部／飲料／零食；新增願望必選飲料或零食，不必填姓名；按「我也喜歡」時必填姓名。願望卡顯示贊同人數，可點開查看姓名，滑鼠移過人數也可預覽；舊票未提供姓名時保留票數並標示未留姓名。同一瀏覽器對同一願望只計一票。
- 停買改為歷史品項，保留庫存與所有舊紀錄；之後可重新上架。歷史卡片可按「我還想喝，希望有機會可以再買」，填姓名後合併到同一個回購願望與贊同名單；同一瀏覽器一票，票數也會出現在採買許願池。
- 管理者可複製補貨清單與匯出盤點／入庫紀錄。
- 桌機插畫使用保留原尺寸的 WebP，下載量約縮小九成。許願／贊同只處理願望資料，收到已儲存摘要即更新畫面；固定 Google 表單網址與完成回條可快取，熱門統計只回傳前三名摘要。Google 新版需更新原部署，詳見 [效能說明](docs/PERFORMANCE.md)。
- 同一區域的頁面使用已讀取的共用資料立即切換；背景與手動更新不鎖住選單。較晚回來的讀取結果不覆蓋新頁面、彈窗或更新期間輸入的內容；資料送出時仍防止重複操作。
- 點飲料可看成分、過敏原與營養欄位；40 款皆已補基本八項營養值，其中 5 款使用已註明的參考包裝或推估版本。成分與過敏原獨立核對，未確認資訊不填成 0。來源、核對日期、份量與原標籤連結一併顯示；八寶粥以公克標示，Moriyama 保留日本原廠的每 100 公克與食鹽相當量範圍。完整查核狀態見 [標示清單](docs/DRINK-LABEL-AUDIT.json)。數據隨網站讀取，點擊不會重新爬網或呼叫 AI。

## 本機試用

開啟 [預覽 ZIP 檔案頁](https://github.com/reytai-hldwn/pantry/blob/main/downloads/holdwin-pantry-preview.zip)，按「Download raw file」下載。解壓縮後以瀏覽器開啟 `demo.html`，包含全部商品圖，不需要額外安裝。儲存庫目前公開；若日後改為私人，下載前須登入有存取權的 GitHub 帳號。

`demo.html` 是可獨立開啟的單檔示範，內嵌程式與品牌圖片。若瀏覽器限制本機檔案，請啟動開發伺服器：

```sh
npm run dev
```

本機示範的修改只存在同一個瀏覽器；這不是正式共用模式。通用預覽的初始數量等待實際輸入，每箱預設 24，不沿用舊示範庫存。私人盤點可用建置器的 `--stocktake 私人.json --output /私人目錄/預覽.html` 產生已帶入數量的版本；輸入及輸出都必須放在儲存庫之外，通用下載與正式網站建置不會包含私人盤點。

## 正式共用：網站原生表單＋Google 試算表

正式網址：[宏穩茶水間](https://reytai-hldwn.github.io/pantry/)。沿用 Google Apps Script 與私人試算表：

- 冰箱讀取品項與願望；免登入的管理入口另外讀取庫存及登記人紀錄。
- 許願、贊同、盤點、入庫及新增飲料沿用 demo 的網站表單，在頁內送出至 Apps Script，不跳轉 Google 表單。盤點、入庫與新增飲料必填登記人，贊同必填姓名，許願不收姓名。
- 只有收到 Google 的儲存回條才顯示成功。重複點擊及逾時重試使用同一筆識別碼，避免重複入庫；同一瀏覽器對同一願望只計一票。
- 持有網站連結者都能查看倉庫並登記數量。原始 Google 試算表保持私人，網站只接受五種指定操作。
- 試算表沿用 `Catalog`、`Warehouse`、`Archive`、`History`、`WishReview`、`WishVotes`、`ProductIntake`；新增 `WebsiteRequests` 保存送出狀態。既有 Google 表單及回應仍保留。

**已接好 Google 的網站，只需由擁有人更新一次 Apps Script 部署版本，才會啟用原生送出。** [更新步驟](docs/GOOGLE-SETUP.md#已有-google-部署更新原生表單)會沿用原 `/exec` 網址、試算表與紀錄，不必重新執行 `setupOnce`。在更新 Google 端以前，網站仍相容既有表單流程。

新專案請依 [Google 設定步驟](docs/GOOGLE-SETUP.md) 建立資源，再依 [網站上線步驟](docs/GO-LIVE.md) 發布 GitHub Pages。桌機與手機的模擬整合測試已通過；實際 Google 同步仍需擁有人更新部署後確認。

既有網站啟用泡麵、碳粉及保存期限，需由原 Apps Script 專案更新 `Code.gs` 並在「管理部署」選新版本；不用重跑 `setupOnce`。更新前網站顯示品項與更新提示，新增的儲存按鈕暫不啟用。[逐步操作](docs/SUPPLIES-SETUP.md)。

## 開發與驗證

Node.js 24、Python 3 即可，不需要 `npm install`：

```sh
npm run build       # 更新單檔示範；同時驗證內嵌模組語法
npm run check
npm test
npm run dev
```

插畫／開門、原生表單與慢速連線下切換頁面的瀏覽器整合測試另見 `tests/browser-scene.mjs`、`tests/browser-native-google.mjs`、`tests/browser-navigation.mjs`；需 Chromium 與 Playwright Core，端點攔截至模擬的 Apps Script／試算表，不會寫入正式 Google 資料。

`tests/browser-release-cache.mjs` 需先建置 `dist/`；它用保留舊 CSS 與模組的真實瀏覽器快取驗證更新，並由本機伺服器提供示範設定，不連線 Google。

`tests/browser-mobile-performance.mjs` 驗證手機延遲載圖、每週飲用量、背景統計與回訪快取，使用模擬 Google 資料，不寫入正式試算表。

首次開啟首頁會先顯示關門的冰箱，Google 資料在背景讀取；讀取中開門會顯示等待狀態。新版 `Code.gs` 提供 `fastReceiptVersion: 1`，讓提交用的 Google 沙盒直接回傳已提交的儲存回條，省去另一趟回條查詢；來源視窗、Google 網域、隨機回覆代號及請求代號均須吻合。舊部署或訊息未送達時仍使用原回條查詢，不以 iframe 載入當作儲存成功。既有 Apps Script 需替換完整 `Code.gs`、儲存並更新原部署的新版本，不用執行 `setupOnce` 或更換網址。

`tests/browser-fast-feedback.mjs` 驗證首次載入期間開門與切換頁面、Google 跨網域巢狀沙盒回條、許願／附議無額外查詢，以及訊息被阻擋時的回退；`tests/browser-gacha.mjs` 另檢查旋鈕兩段半圈、出球、開殼、展開籤詩、保留今日結果的動畫重播，以及全部 39 支籤詩依逗號換行、不留下孤立字或標點。動畫與排版只需發布前台，不需更新 Apps Script。兩者均使用虛構資料。

`tests/browser-supplies.mjs` 驗證桌機與手機的用品單位、效期分批與提醒、三個到貨子頁與分類紀錄、庫存排序、條件式新品欄位、必填與重複送出、跨瀏覽器讀取及舊部署提示；Google 寫入使用記憶體模擬。

`tests/browser-restock-preferences.mjs` 驗證人工勾選補貨、優先排序、取消後恢復一般字色、跨瀏覽器同步、複製清單排除與排序匯出；同時確認數量及泡麵效期維持不變。

正式站以 `GOOGLE_SCRIPT_URL` 設定已發布的 `/exec` 網址，再執行 `npm run build:site`。建置只輸出網站必要檔案到 `dist/`，不包含試用檔、設定腳本、測試或截圖；沒有共用網址會拒絕建置，不會發布各手機獨立的本機示範。

正式建置會依 HTML、CSS、JavaScript、字型與公開設定產生一致的版本參數，套用到入口、所有本機模組匯入及字型預載／CSS，避免新版頁面沿用舊樣式、字型或 `fridge.js`。版本資訊放在 HTML 的 `pantry-release` metadata；原始檔與單檔示範不受改寫。

`supabase/` 與舊設定文件保留為選配介接參考，目前的正式上線流程以 Google 為準。

`tests/browser-inventory-workflows.mjs` 驗證桌機與手機的混合批次、必填日期與保留草稿、首次入庫數量、口味編輯、人工補貨標紅與排序、零食快速盤點及單次首頁摘要讀取。

到貨入庫右側顯示各類最近 72 小時內的全部紀錄，沒有五筆上限；較早紀錄仍可在異動紀錄查閱。

歷史品項也可由單筆或批次入庫的選單選取，放在供應中選項後並清楚標示；儲存成功才恢復供應，沿用原 ID、圖片、營養資訊、單位、既有庫存及歷史，不另建重複品項。

後台歷史品項可勾選「需要補貨」，包含自動歸零與手動停供品項；勾選會列入總覽「準備補貨」及本頁補貨清單，品項仍維持歷史狀態與原庫存。此功能需新版 Apps Script 的 `restockPreferenceEntry.archivedVersion: 1`；舊部署仍可操作原有自動歸零品項的勾選，其他歷史品項會提示更新。`drink-name` 指令以原品名核對並記錄更名，僅更新原 Catalog ID 的名稱，保留異動、圖片與庫存；本次蜂蜜燕麥全名為「愛之味蜂蜜燕麥」。

`tests/browser-archived-restock.mjs` 使用虛構資料檢查手機／桌機歷史勾選、取消、總覽、複製、跨瀏覽器同步及舊部署提示；不向正式資料送出測試補貨勾選。

後台會在總覽顯示後預讀庫存，完整讀取結果僅於同一分頁記憶體重用 30 秒；實際數量與異動不寫入瀏覽器持久快取。返回總覽可沿用已驗證庫存計算摘要，過期摘要會標示讀取時間與更新狀態。資料端提供庫存 8 秒、摘要 15 秒的短期快取，網站寫入及來源工作表編輯會換用新版本；手動重新讀取會跳過快取。

新版 `restockPreferenceEntry.fastVersion: 1` 的補貨回條會直接更新已確認的勾選與摘要，省略整份庫存重讀；資料端只更動對應的產生檢視標示儲存格，盤點／入庫仍重建完整檢視。原請求日誌、三階段 flush、重試去重及 expectedMode 衝突檢查保留；舊部署或不完整回條使用原本的重讀流程。完整重建時重新排序試算表，網站則依共用設定即時排序。

`tests/browser-admin-speed.mjs` 可搭配 `PANTRY_BASELINE_ROOT` 比較相同網路延遲下的勾選、總覽與庫存切換；`tests/admin-speed.test.mjs` 驗證快取過期／失效、確認回條、延遲舊回應、衝突恢復與資料範圍。
