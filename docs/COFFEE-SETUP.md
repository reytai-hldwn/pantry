# 咖啡豆庫存與到貨入庫

咖啡豆是「倉庫庫存」與「到貨入庫」的子分頁，沒有獨立的側邊選單。到貨入庫位於 `#restock-coffee`；先前的 `#coffee` 連結會自動轉到這裡。

品項只登記品牌、每包重量（磅）、包數，登記人沿用其他入庫表單的共同必填欄位。每包預設 0.5 磅，以半磅遞增，表單附註「半磅約 227 公克；1 磅約 454 公克」。每筆小計、入庫日總重量與庫存總重量都以磅顯示。

入庫日期與其他分類一致：送出時由系統自動記錄，不提供手動收貨日期欄位。Google 模式採用資料端時間，本機示範採用瀏覽器時間，顯示及每日摘要均以台北時區計算。摘要顯示最近入庫日、該日所有入庫的總包數與總磅數；實際盤點不算入庫。

## 操作

- **倉庫庫存 → 咖啡豆**：相同品牌與相同每包重量合併庫存；同品牌不同重量分列。顯示每包磅數、庫存包數、庫存總磅數及最近入庫時間。手機以卡片呈現。
- **快速入庫**：點庫存列的「＋ 快速入庫」，沿用該列品牌與每包重量，填本次包數及登記人，儲存後累加庫存。
- **盤點**：填實際剩餘包數，0 表示已用完。盤點校正目前庫存，不更改最近入庫日期或當日到貨總量。
- **到貨入庫 → 咖啡豆**：填品牌、每包磅數、包數及登記人。相同品牌與包裝沿用原庫存，新的包裝自動建立。
- **批次多品項入庫**：可與飲料、零食等分類混合送出，整批先驗證再儲存；咖啡豆列維持品牌、磅數與包數。
- **紀錄與匯出**：咖啡豆入庫及盤點可在共用「異動紀錄」查閱；咖啡豆庫存 CSV 分開匯出每包磅數、包數與總磅數。到貨頁顯示最近 72 小時紀錄。

## 已有 Google 部署的更新

1. 將儲存庫的 `google-apps-script/Code.gs` 完整貼入原 Apps Script 專案，儲存。
2. 在「部署 → 管理部署」編輯原部署，選擇「新版本」並部署，沿用原 `/exec` 網址。
3. 發布新版網站後，開啟「到貨入庫 → 咖啡豆」，按「重新整理」。

不需重跑 `setupOnce`。新版提供 `coffeeEntry.version: 2`；舊部署仍可讀取先前紀錄，入庫與盤點表單會停用並提示更新，避免沿用舊版的手動收貨日期。

第一次實際寫入才會建立私人試算表的 `CoffeeReceipts` 工作表，單純讀取不建立資料。保存事件 ID、入庫／盤點時間、系統日期、品牌、每包磅數、包數、登記人與類型（`restock` 或 `count`）。先前七欄的咖啡豆紀錄仍保留，類型視為入庫，第一次新寫入才補上第八欄；每日入庫摘要統一依原始登記時間計算。

寫入沿用 `WebsiteRequests` 的確認回條與相同請求代號重試，避免重複入庫。批次先驗證所有列，再合併寫入；每個品牌與包裝的庫存上限 999999 包。咖啡豆不改動既有飲料、零食等來源紀錄，前台公開清單也不包含咖啡豆或登記人資料。

本機示範僅保存在同一瀏覽器，不跨裝置共用。驗證：`node tests/coffee.test.mjs`；手機與桌機流程：`node tests/browser-coffee.mjs`（需 Playwright 與 Chromium，使用虛構 Google 資料）。
